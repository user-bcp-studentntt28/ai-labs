API + flujo humano local
Fuentes de operación desde API; seguimiento humano en este navegador: los estados y comentarios de analista/supervisor se guardan en localStorage y no modifican el API ni se comparten con otros usuarios o dispositivos.

Conexión y ejecución

Wallet, settlements, ledger e incidencias se consultan desde el mismo grupo.
Carga las fuentes para consultar la información actual del API.
1

Preparar fuentes

Los pagos se crean y confirman por W2. Este panel consulta pagos, settlements, ledger e incidencias del grupo.

2

Conciliar

POST /reconciliations compara pagos, reporte, asientos y saldos.

3

Revisar resultado

Consultar incidencias OPEN o RESOLVED devueltas por el API.

4

Repetir tras corregir

Analista actualiza fuentes y vuelve a conciliar; la API resuelve si desaparece la causa.

5

Validar cierre

Supervisor revisa las fuentes y confirma RESOLVED. El visto bueno es local a esta sesión demo.

APIs consultadas: GET /payments?walletId=..., GET /settlements, GET /ledger, GET /reconciliations/incidents. Ejecución: POST /reconciliations.

Control de prueba del proveedor: altera únicamente el reporte de settlements del API; no cambia wallet ni ledger. Después de aplicar un escenario, vuelve a ejecutar la conciliación. Usa CLEAR para restaurar el settlement de un pago.

Roles del flujo de atención

El analista investiga; el supervisor valida la resolución.
ANALISTA

Inicia la atención, revisa las fuentes, registra qué encontró y qué corrigió, y envía el caso a revisión del supervisor.

SUPERVISOR

Revisa notas y fuentes; aprueba el cierre local o devuelve el caso al analista con observaciones.

Demo sin autenticación: el selector de rol permite probar el flujo, pero no verifica identidad ni permisos. Los cambios se guardan en localStorage de este navegador; no se envían al API y no son una aprobación operativa real.
